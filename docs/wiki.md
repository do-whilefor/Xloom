# Wiki 与来源关系

Xloom 在现有研究任务内生成 Wiki，不启动 Webounty 会话、Python 引擎、额外
Agent、执行工具或 hook。现已包含阅读导航、有来源的作者解释、来源变化提示、
任务内词法与模型辅助 RAG、原文检索、增量缓存、跨轮资料交接、本地整理／审计及原生能力/链路记录；CVSS 与[观察比较器](observation-comparison.md)也已原生接入。能力组合见 [原生能力与链路](knowledge.md)。

## 存储与阅读

Wiki 位于用户目录下当前任务的 `wiki/index.md`、`wiki/pages/` 和
`wiki/manifest.json`，与 `blackboard.sqlite`、`evidence/` 同级。典型位置为
`C:\Users\Acer\.xloom\projects\<项目ID>\tasks\<任务ID>\wiki\index.md`。
`XLOOM_HOME` 指定其他用户数据目录时同样沿用。任务结束不会删除 Wiki。

SQLite 仍是正式记录的唯一权威；作者页面保存在黑板的可选 `wikiPages` 中，
与现有 Execution 和 checkpoint 同事务提交。Markdown 和 manifest 都可重建。
无需旧库字段迁移：没有作者页面的旧任务从已有黑板生成自动页。

首页按目标、活动或受阻步骤、未解决 Finding、已确认影响、关闭命题、作者解释、
条件化尝试、事实修订、历史步骤和证据入口分组。自动页列出公开记录及其明确引用，
不复制原始响应和私有会话，也不根据文本自行归纳新结论。

每次研究调用包含 `wiki` 导航信息和独立的 `rag` 检索上下文。Execute 另有安装包内的 `authoringGuide`
路径，必要时用原来的 read 阅读；其他角色仍只有原来的工具权限。相关解释按完整块
进入 `rag`，不整体注入系统提示词或角色黑板。普通聊天不加载 Wiki/RAG，历史也不写入 Wiki。
这些入口及后续读取仍会消耗上下文；没有实测保证 token 降低。

## 作者解释

现有 Execute 最终输出或 checkpoint 的 execution 可带 `wikiPages`。结构示例及
全部规则见 [安装包编写说明](../resources/wiki/authoring.md)。每页含稳定 ID、标题
和判断块；每块含稳定 ID、标题、正文与带类型的 sources。来源类型为 goal、step、
fact、finding、evidence、attempt、capability、chain，必须属于当前任务；fact/evidence 可以使用同批
新提交的局部 ref，Store 会转换为正式 ID。capability/chain 可引用本批提交的稳定 ID。其他类型使用已提交 ID，Finding key
不能冒充 Finding ID。已提交 checkpoint 的 ID 可用于同一次 run 后面的最终输出。

一块保留一个完整判断及其适用条件、否定或未知范围。引用 Goal/Step 可以说明计划，
不代表计划已经执行。作者解释不是原始证据；系统拒绝将保留 Xloom Wiki 标记的
生成页复制件归档为证据，但不能靠这个标记识别任意改写的叙述或证明材料真实性。

复用页面 ID 可以改名、修订解释和调整块。修改正文时提交完整页面；省略的旧块退出
当前正文但保留在历史解释中。也可更新标题、父目录及页/块检索元数据，这些更新保留
原有来源基线；没有单独的页面删除协议。来源与正文完全相同的重投递不新增作者修订；checkpoint 本身仍按
既有 ID/内容幂等规则处理。仅写 Wiki 不增加事实、证据、研究进展或完成状态。

每次最多提交 16 页，每页最多 32 块，每块正文最多 16,000 字符、来源最多 64 项。
这是可选输出结构限制，不是整个研究任务、历史存储或模型 token 的上限。

## 来源变化与复核

Store 在作者提交时保存所引用公开记录及明确依赖的内容签名；涉及证据的来源在
提交时验证归档大小和哈希。事实的来源条件、supersedes 双向链、明确声明的反证、
相关尝试和 Finding 的事实/证据关联共同参与依赖检查，循环引用会终止遍历。
相同证据或精确假设标识关联的尝试只是复核线索，不能保证身份、范围和环境相同。

以后记录变化或缺失时，首页、当前解释页及 manifest 列出待复核块、来源 ID 和原因，
正文保留作者原来的判断。来源变化不自动否定旧观察，也不直接改变 Finding 状态。
无明确关系的其他任务、无关新增材料或私有 run 字段不会成为来源变化依据。

必须阅读变化材料并显式重新提交完整页面，才能更新作者所声明的来源基线。允许
复核后保留原文字；读文件、重启程序或改名生成的 Markdown 都不表示已复核。
改用新来源后，旧版本正文与来源仍保留在历史部分。

派生 Fact 的前置事实被更正或缺失时，公开记录添加 `basisReview` 和
`basis_review_required`，沿明确因果依赖传播。Wiki、检索及能力/链路复核都能看见该
标记；仅重存页面或能力不能使旧派生判断重新有效。显式更正 Fact 可以保留被替代的
旧记录作为历史，同时使用当前前提；旧记录仍参与来源签名和冲突检查，直接引用旧
派生判断仍要求复核。这只追踪已声明的关系，无法验证自然语言推理是否正确。

“来源记录未变”仅表示已登记元数据与作者提交时一致，不是当前漏洞成立或文件
完整性的证明。生成页面不重复读取全部证据原件；实际 Finding 审查仍经过 Store
的证据校验，读取者仍需核对原件。未表达的依赖和自然语言反证无法自动追踪。

## RAG、本地整理与审计

详见 [本地检索与审计](retrieval.md)。检索从当前 SQLite 快照读取完整 Wiki 判断块、
公开 Goal/Step/Fact/Finding/Attempt 及证据元数据，使用中文二元词、接口标识组成词
和标题加权的词法排名；精确引用优先，并补齐明确来源、更正关系及相关尝试。
这个元数据索引不收录原始响应正文；正文由独立的原件窗口索引按需检索。
作者历史、私有会话、其他任务和外部 Webounty 文件不进入上述索引。

每次打开／提交后自动生成 `wiki/search-index.json` 和 `wiki/organization.json`，
并登记到 manifest 哈希列表。它们是可重建的派生文件；查询从 SQLite 重建内存索引，
不信任可能被手改的磁盘索引，也不清除作者来源变化标记。当前版本从公开快照构建
记录，复用任务内 SQLite 词项缓存；原件支持全文窗口检索和定位精读。跨轮导航
交接保存在正式 SQLite 的 material_receipts 中。显式语义入口使用已配置模型扩展查询、
生成逐块检索提示并重排，派生提示按来源内容签名持久保存；没有向量服务依赖。
所有研究角色可通过现有 read 主动搜索 Wiki、原件及指定消费者的能力前提，见 [原生查询入口](retrieval.md#原生主动查询)。

整理列出主题、待复核块、缺失引用、替代事实、相同全文和未关联证据，供人工／模型
复核，不按词面相似自动合并或删除内容。显式 `audit` 检查生成文件与 SQLite 是否一致，
流式核对已登记原件的大小及 SHA-256，并检测检查期间的文件／黑板变化。
完整性一致不表示语义判断正确。保留生成标记的 RAG／整理／审计 JSON 同样不能作为
原始证据提交。既有 Agent、工具列表和角色系统提示词保持不变。

## 失败与恢复

非法页面来源会在最终输出的无工具纠正之前诊断；Store 仍做事务内检查。
checkpoint 的错误按既有工具结果返回。来源不合法或作者提交时原件损坏，会回滚
该批黑板、Wiki、用量和事件；此前已成功 checkpoint 的资料保持可用。与原有证据
提交一样，验证失败可能留下未被引用的归档文件，程序不自动删除研究材料。

页面生成发生在数据库提交后。磁盘或受保护文件导致失败时，Controller 报告 Wiki
投影不可用并保留已提交资料；后续任务打开或更新会尝试重建，不重放执行操作。
现有非生成文件保留，目录与文件符号链接拒绝作为投影目标。单文件原子替换，页面
先于首页和 manifest 发布。projection-state.json 先标记 building，完成页面发布、
旧生成页清理及 manifest 更新后才标记 ready，并绑定修订和 manifest 哈希。
旧 manifest 保留至清理成功，以便中断后重试。普通 Wiki 文件读取会拒绝未完成或过期
投影，原生 SQLite 检索仍可用；这不是全目录原子快照，失败时应以不可用提示为准。
直接编辑生成页不会反向导入数据库，后续成功生成会恢复权威内容。

## 验证与来源

测试覆盖来源 ID、同批引用、事务回滚、checkpoint、重启、历史版本、事实替代、
条件和反证提示、页面生成失败、派生材料隔离及真实 Pi read/write 的跨角色读取。
自动化测试使用合成材料和模拟模型响应；另有直接调用项目配置模型的
[Wiki 与 RAG 优化回放](wiki-rag-optimization-validation.md)。这些验证不能推算真实任务
的解释准确率或漏洞判断能力。

组织方式参考本地 Webounty 的 `references/wiki-layout.md` 与 `references/storage.md`：
按完整判断保存条件和来源、稳定页面身份、保留旧解释并标记变化。本阶段使用 Xloom
原有数据模型重新实现，没有复制其 state.json、独立会话生命周期或整套 Python 运行时。

## 观察变化与知识准确性

现有 Attempt/Evidence 比较已原生接入，详见[观察比较与复核](observation-comparison.md)。
同条件相反观察、事实更正和 Finding 来源变化会随来源包展示。不同观察文字分别保留，
重复 outcome 仍不计新进展。Wiki 重新保存不能消除底层冲突；检索与阅读不是复核回执。
